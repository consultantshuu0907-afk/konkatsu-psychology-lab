# 婚活心理ラボ（GitHub Pages版サイト）

このフォルダには、GitHub Pagesで無料公開できる婚活アフィリエイトサイトの一式が入っています。WordPressのようなサーバー契約は不要で、GitHubに置くだけで公開できます。

## 公開までの手順（初回のみ）

1. **GitHubアカウントを作る**（すでにお持ちならこの手順は不要）
   https://github.com/ にアクセスし、無料登録します。

2. **新しいリポジトリを作る**
   - 右上の「+」→「New repository」
   - Repository name：`konkatsu-site` など好きな名前（後述の②を使う場合は `あなたのユーザー名.github.io` にすると手順が簡単になります）
   - 「Public」を選択（GitHub Pagesを無料で使うにはPublicにする必要があります）
   - 「Create repository」をクリック

3. **このフォルダの中身をアップロードする**
   - 作成したリポジトリの画面で「uploading an existing file」または「Add file」→「Upload files」をクリック
   - このzipを展開してできたフォルダの中身（_posts、_layouts、_includes、assets、category、index.md、about.md、privacy.md、contact.md、_config.yml、README.md）を**フォルダごと**ドラッグ＆ドロップでアップロード
   - 下部の「Commit changes」をクリック

4. **GitHub Pagesを有効にする**
   - リポジトリの「Settings」タブ→左メニューの「Pages」
   - 「Source」を「Deploy from a branch」にする
   - 「Branch」を「main」／フォルダは「/ (root)」に設定して「Save」
   - 数分待つと、ページ上部に公開URL（例：`https://あなたのユーザー名.github.io/konkatsu-site/`）が表示されます

5. **URLの設定を合わせる（重要）**
   - リポジトリ名を `あなたのユーザー名.github.io` にした場合：`_config.yml` の `baseurl:` は空欄のままでOKです。サイトは `https://あなたのユーザー名.github.io/` で公開されます。
   - リポジトリ名をそれ以外（`konkatsu-site` 等）にした場合：`_config.yml` を開き、`baseurl: ""` の部分を `baseurl: "/konkatsu-site"`（リポジトリ名に合わせる）に変更してアップロードし直してください。これをしないと、ナビゲーションやCSSのリンクが正しく表示されません。

## 独自ドメインを使う場合

1. `CNAME` という名前のファイル（拡張子なし）を作成し、中身に独自ドメイン（例：`www.konkatsu-lab.com`）だけを1行書いてアップロードする
2. ドメインを購入したサービス（ムームードメイン等）の管理画面で、GitHubの指示に従いDNSレコード（Aレコード／CNAMEレコード）を設定する
3. 詳細はGitHubの公式ヘルプ「Managing a custom domain for your GitHub Pages site」を参照してください
4. 独自ドメインを設定した場合は、`_config.yml` の `url:` にそのドメインを記入し、`baseurl:` は空欄のままにしてください

## 新しい記事を追加する方法（2回目以降・とても簡単）

1. リポジトリの `_posts` フォルダを開く
2. 「Add file」→「Create new file」
3. ファイル名を `2026-08-20-記事のスラッグ.md` のように「日付-半角英数のタイトル.md」の形式で入力（日付は公開日）
4. 中身に、既存の記事ファイル（例：`2026-08-16-konkatsu-tsukareta.md`）と同じように、先頭に

   ```
   ---
   title: "記事タイトル"
   description: "検索結果に表示される説明文（120文字程度）"
   date: 2026-08-20
   categories: [結婚相談所]
   psychology_principle: 使った心理学の原則名
   faq:
     - q: "よくある質問1"
       a: "その回答"
     - q: "よくある質問2"
       a: "その回答"
   ---
   ```

   を書き、その下に本文（Markdown）を貼り付ける（`faq:` は任意項目ですが、書いておくと検索エンジンやAI回答エンジンにFAQとして認識されやすくなります。詳しくは下記「SEO・AIO対策」参照）
5. 「Commit changes」をクリックすれば、数分後に自動で公開されます（ビルドやアップロードの追加作業は不要です）

**アイキャッチ画像について**：`image:` front matterで指定した画像（例：`/assets/img/eyecatch/新しい記事のスラッグ.png`）が、記事一覧のサムネイルと記事ページ上部に表示されます。画像自体はJekyllが自動生成するものではないため、新しい記事を追加する際は、Claude（Cowork）に「この記事のアイキャッチ画像も作って」と頼めば、既存の12記事と同じデザインで自動生成できます。`image:` を省略した場合は、`_config.yml`の`defaults`で指定したサイト共通画像（`assets/img/ogp.png`）が使われます。

Claude（Cowork）に「次の記事を書いて」と頼めば、この形式のMarkdownファイルをそのまま作成できるので、それをコピーしてアップロードするだけで運用できます。

## カテゴリーについて

記事の `categories:` に使える値は、ナビゲーションと連動して以下の4種類です（複数指定可）。
- `マッチングアプリ`
- `結婚相談所`
- `属性特化型婚活`
- `婚活の悩み・心理`

新しいカテゴリーを追加したい場合は、`category` フォルダに同じ形式のファイルを追加し、`_includes/header.html` にリンクを1行追加してください（Claudeに頼めば対応できます）。

## サイト運営者情報・PR表記について

`_config.yml` の `author:` と `pr_notice:` を書き換えると、サイト全体の運営者情報・広告表記（フッターと各記事に自動表示）が一括で更新されます。

## UI/UXの機能（2026/08/16 追加）

デザインとユーザー体験を強化しました。記事を追加するだけで、以下はすべて自動的に反映されます（追加の作業は不要）。

- **スマホ対応ナビゲーション**：画面幅が狭いとハンバーガーメニュー（三本線）に切り替わり、タップで開閉します
- **カテゴリー別の色分けタグ**：マッチングアプリ＝青、結婚相談所＝ローズ、属性特化型婚活＝アンバー、婚活の悩み・心理＝グリーンで自動的に色分けされます
- **自動目次**：見出し（##）が2つ以上ある記事には、本文の上に目次が自動生成され、クリックで該当箇所にジャンプします
- **読了目安時間**：文字数から自動計算され、日付の横に表示されます（`_layouts/post.html`が計算するため記事側での入力は不要）
- **カード型の記事一覧・ホバー演出**：トップページやカテゴリーページの記事一覧がカード形式になり、マウスを乗せると少し浮き上がります
- **テーブルのスマホ対応**：比較表が画面からはみ出す場合、横スクロールできるようになります
- **トップへ戻るボタン**：記事を下までスクロールすると右下に表示されます
- **404ページ**：存在しないURLにアクセスした際の案内ページ（`404.md`）を追加しました
- **記事ごとのアイキャッチ画像**：カテゴリーの色×記事タイトルを組み合わせたオリジナル画像を12記事すべてに自動生成し、記事一覧のサムネイルと記事ページ上部に設置しました（`assets/img/eyecatch/`）。SNSやAI検索でシェアされた際の画像（OGP画像）としても同じ画像が使われます

これらはすべて `assets/css/style.css` と `assets/js/main.js`、各レイアウトファイルに組み込み済みです。デザインを調整したい場合（色味やフォントサイズなど）は、`assets/css/style.css` の冒頭にある `:root` 内の色変数を書き換えるだけで、サイト全体に反映されます。

## SEO・AIO対策（2026/08/16 追加）

検索エンジン（Google等）およびAI回答エンジン（ChatGPT検索、Perplexity、Google AI Overviews等）向けの基本的な対策を組み込み済みです。GitHub Pages標準の安全なプラグイン（追加のインストール作業やGemfile不要）を使っています。

**自動的に有効になっているもの**
- **sitemap.xml の自動生成**（`jekyll-seo-tag`ではなく`jekyll-sitemap`）：検索エンジンに全ページを伝える一覧を自動作成
- **canonical URL・OGP・Twitter Card・構造化データ(JSON-LD)の自動出力**（`jekyll-seo-tag`）：SNSやAI検索でシェアされた際に、タイトル・説明文・画像（`assets/img/ogp.png`）が正しく表示されます
- **FAQPage構造化データ**：各記事の「よくある質問」を`faq:`front matterに書いておくと、記事ページに自動でFAQ用の構造化データ（JSON-LD）が出力されます。これはGoogleの検索結果やAI回答エンジンが記事内容を正確に引用・要約する助けになります（既存の記事12本はすべて自動で変換済みです）
- **RSSフィード**（`jekyll-feed`）：`/feed.xml`が自動生成され、新着記事をAIクローラーや購読者に伝えやすくなります
- **robots.txt**：標準的な検索エンジン・AIクローラー（ChatGPT、Perplexity、Google等）のアクセスを許可する設定にしています。特定のクローラーだけを拒否したい場合は、`robots.txt`に`User-agent: <bot名>`＋`Disallow: /`を追記してください（例：AI学習目的のクロールだけ拒否したい場合など）
- **llms.txt**：AIエージェント・LLM向けに、サイトの概要と全記事へのリンク一覧をシンプルなテキスト形式でまとめたファイルです（提唱され始めている新しい規格で、対応は今後のAIサービス次第ですが、コスト無しで設置できるため追加しました）

**公開後、しゅうさんご自身で行うと良いこと（当サイト構築だけではカバーできない範囲）**
- **Google Search Console**への登録とsitemap.xml送信（インデックス状況の確認に必須）
- 記事の**独自の一次情報・体験談**の追加（AIによる要約だけでなく、しゅうさんの婚活支援の実務経験を活かした一次情報が、E-E-A-T評価やAI引用のされやすさに直結します）
- 他サイト・SNSからの**被リンク獲得**（SEO評価に影響しますが、当サイトの中身だけでは作れません）
- 定期的な記事更新・情報の鮮度維持

SEO・AIOは「これをやれば必ず上位表示される」という保証があるものではなく、技術的な土台を整えることが目的です。中身（記事の専門性・信頼性）を伴わせることが最も重要である点にご留意ください。
